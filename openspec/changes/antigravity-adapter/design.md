## Context

**Verified on Antigravity CLI 1.4.4** (2026-10-21, recorded in `docs/pilot-findings.md`):

- Plugins: `agy plugin install <folder | github url | name@marketplace>`; a folder with `plugin.json` (strict schema), `skills/<name>/SKILL.md`, `agents/*.md`; a plugin `relevo` with a skill `go` is `/relevo:go` ([plugins](https://antigravity.google/docs/plugins?tab=cli)). A Claude Code plugin is converted on install, but its agents are copied unchanged. A project plugin in `<project>/.agents/plugins/<name>/` is read by the CLI; the machine one is staged under `~/.gemini/config/plugins/` (the IDE and the App read it too).
- Skills: `disable-model-invocation: true` is honoured, `$ARGUMENTS` expands when typed as `/name args`. **No script path variable exists**: `${CLAUDE_PLUGIN_ROOT}` and `${PLUGIN_ROOT}` are not substituted, and the model improvises a `find`, which is fragile and defeats a command allow rule.
- Agents: Markdown with frontmatter; `tools` must be a YAML list of the tool's own names (`run_command`, `view_file`, `write_to_file`, `replace_file_content`, `grep_search`, `find_by_name`, `list_dir`, …) and is honoured on top of a fixed base; `disallowedTools` is ignored; `model: sonnet` or a string `tools` make the agent fail to load; with no `tools` it gets reading tools only. In a native plugin an agent's name is the one in its frontmatter. `agents.json` takes `{"entries":[{"path":…}]}`.
- Headless: `agy -p --output-format json|stream-json`; `--print-timeout` defaults to 0 (the docs say 5 minutes), so it is always passed. The stream has one event per step with its tool and token usage; `num_turns` counts user turns only. A rule `command(curl)` in `deny` blocks and the step ends in `ERROR`; a command no rule allows is auto-denied in headless mode; both leave the run `SUCCESS` with exit 0, and the second adds `denied_actions` to the JSON and a message on stderr. A subagent call does not block; its result arrives later inside the same run.
- Credentials for CI ([authenticate](https://antigravity.google/docs/install/)): `"modelProvider": "gemini"` in the user settings plus `GEMINI_API_KEY` is documented as the headless and CI path (`GOOGLE_API_KEY` and `.env` are ignored); ADC with `AGY_ADC_AUTH=true` is the other. Whether it works on a runner is task 1.5. The issue asking for it ([#78](https://github.com/google-antigravity/antigravity-cli/issues/78)) was closed 2026-09-21 with mixed signals in its thread. The earlier hang of `agy -p` without a terminal ([#318](https://github.com/google-antigravity/antigravity-cli/issues/318)) was reported on 1.2.x and did not reproduce here.
- Workflows (`.agent/workflows/`) stopped being indexed after 2026-10-19 ([migration](https://antigravity.google/docs/migration/workflows-to-skills/)); this change uses none.
- **Gemini CLI** is not used: its pages say Antigravity CLI replaced it for unpaid and Google One users on 2026-06-18. Its action `run-gemini-cli` stays the fallback for the cloud step if the `agy` runner check fails.
- **OpenSpec as reference** (`@fission-ai/openspec`): a tool-agnostic content plus one small adapter per tool. We take the shape only.

**What in the sources is neutral.** The bodies are English prose plus calls to `node ${CLAUDE_PLUGIN_ROOT}/scripts/<x>.mjs`, `gh` and `git`. The scripts find `stacks/` and `templates/` from their own location, so a copy of `scripts/`, `stacks/` and `templates/` next to the skills works. The ties to Claude Code are: the agent frontmatter (`model`, `effort`, `disallowedTools`), `${CLAUDE_PLUGIN_ROOT}` (about 90 uses), the names `relevo:dev` and `relevo:qa` with "launch the agent" (`go`, `fix`, `review`), and `Task` in the workflow's tool list. Skill frontmatter and `$ARGUMENTS` work unchanged.

## Goals / Non-Goals

**Goals:**
- Run Relevo from the Antigravity IDE, App and CLI with the same commands as in Claude Code.
- `relevo init` asks tools and scope; what it installs can be updated, checked and removed.
- A cloud build with `agy` whose limits are real (enforced by Relevo's guard where the tool has none) and whose gaps are stated.

**Non-Goals:**
- Gemini CLI, Claude file generation, any change to the Claude plugin.
- Proving that QA is as good with a Gemini model.
- Antigravity's browser, artifacts and review panels.

## Decisions

- **Render a native plugin, do not convert and do not generate loose files.** The conversion alone leaves the script path and the agents broken, and loose skills would lose the `/relevo:` namespace. A renderer `{ id, render(source, ctx) → folder }` writes `plugin.json` (`name: relevo`, the package version), `skills/<name>/SKILL.md`, `agents/relevo-dev.md` and `relevo-qa.md`, and copies `scripts/`, `stacks/` and `templates/`. It is pure; installing is done by `init`. Source stays in Claude Code's format; no duplicate is edited by hand. Another tool later is one more renderer.
- **The installed path is written into the text at render time.** `node ${CLAUDE_PLUGIN_ROOT}/scripts/x.mjs` becomes `node <absolute folder of the rendered plugin>/scripts/x.mjs`. Alternatives: `relevo run x` through the PATH (rejected: a second moving part and a possible version difference between the package and the plugin) or leaving the variable (verified to fail). Because the path is absolute, `command(node)` is enough for an allow rule. Rendering per install is what makes the path true on a runner and on a machine.
- **Names.** Commands keep `/relevo:<name>` through the plugin namespace. The agents are `relevo-dev` and `relevo-qa` (a colon is not allowed in an agent name); the text `relevo:dev` becomes `relevo-dev` and a test fails if `relevo:dev` or `relevo:qa` remains.
- **Agents are rewritten, not copied.** Frontmatter becomes `name`, `description`, `tools` (YAML list of the tool's names) and the execution policy; Claude-only keys are dropped. `relevo-qa` lists reading, searching and command tools and no write or edit tool, mirroring `disallowedTools: Write, Edit`; its command tool can still write, as Claude's Bash can, and the diff check of `go` stays the real control. `relevo-dev` lists reading, writing, editing, searching and command tools. A table maps each Claude tool to Antigravity's (`Bash` maps exclusively to `run_command`, omitting non-existent tools like `command_status` that cause executor creation failures); the renderer fails on a tool it cannot map, and a test compares the table with the tool names the installed `agy` reports in its `init` event. The default `commandExecutionPolicy` is left as it is: a subagent with a command tool ran the stack-like commands, network included, under it (task 1.3).
- **Reserved skills stay reserved.** `disable-model-invocation: true` is kept as it is, because it is honoured. The security page can state this as enforced by the tool.
- **Orchestration stays in the main session via Reactive Wakeup.** In Antigravity, subagents run in the background and their results arrive as messages. The rendered text of `go` instructs the main agent to yield its turn without calling tools (explicitly forbidding polling with `manage_subagents` which caused busy loops). Antigravity reactivates the main agent automatically when the subagent finishes. The guard fails a run that ends with the issue still `building`.
- **Scope.** Project: render into `.agents/plugins/relevo/` (read by the CLI, verified; the IDE and the App read the same folder). Machine: render into a temporary folder and run `agy plugin install <folder>`. The cloud runner uses the machine route, so the working tree stays clean for the preflight. A file `.relevo-adapter.json` inside the rendered plugin records tool, package version and the hash of each file; `update` renders again and reports a hand-edited file instead of overwriting it unless `--force`; `doctor` reads the same file. The strict `plugin.json` schema is why it is a separate file.
- **The run guard is Relevo's, not the vendor's.** `agent-guard.mjs` starts `agy -p … --output-format stream-json --print-timeout <n>` as a child in its own process group, counts steps and tokens from the events as they arrive, enforces `limits.run_max_turns` (steps of the agent), `limits.run_max_tokens` and a wall-time limit, kills the group at a limit and exits with a code the workflow maps to the "ended without an outcome" comment the Claude template already posts. It fails the run when the final event has `denied_actions` or a tool step ended in `ERROR` with a permission message, because the vendor exits 0 in both cases. It is plain Node with the child injected, tested with a fake process.
- **Cost.** `agy` has no cost limit. `limits.run_max_cost` is rejected by `validate-config` for `agent.build: antigravity`, with a message that says why; `limits.run_max_tokens` replaces it. The ceiling that really holds is the quota and budget of the Google Cloud project the key belongs to, and the pages say that a budget alert is not a cap.
- **Cloud controls**, written on the runner to `~/.gemini/antigravity-cli/settings.json` (outside the repository, so a pull request cannot loosen them): `modelProvider: gemini`; `permissions.deny` for `read_url`, `execute_url`, `command(curl)` and `command(wget)`; `permissions.allow` closed to workspace file actions plus `command(node)`, `command(git)`, `command(gh)`, `command(openspec)` and the commands of the stack profile; `GEMINI_API_KEY` from the secret store. The allow list is a prefix list, not an operating-system boundary: `node` can run any script, as Claude's Bash can, and the security page keeps saying so. A rule is matched against each command of a chain (`a && b`, `a | b`), `cd` needs none, and a subagent inherits the parent's rules (task 1.3), so the allow list names every program the skills pipe into (for example `cat`, `grep`, `sed`, `head`) as well as the stack's tools, and a test lists the programs the skills call and fails if one is missing from the allow list.
- **One workflow template, with the model step in a marked block.** `relevo-go.yml` keeps the whole workflow and marks the model step with `# relevo:agent-step begin` and `end`; for `agent.build: antigravity` the generator that already writes the workflow replaces only that block with `templates/agents/antigravity-step.yml`. A change to the gates, the queue or the reports is made once. Rejected: two templates kept equal by a test, and a templating language. The usage report reads the guard's summary instead of the vendor's log.
- **`relevo init` and the skill `init` are different things** (a tool's plugin versus the repository's labels and rules). The command keeps the requested name, says at the end that the other step exists, and `docs/install.md` has one paragraph on it.

## Risks / Trade-offs

- [`GEMINI_API_KEY` is in the environment of the agent's commands, so the agent can read it] → a dedicated key limited to the Gemini API in a project with a quota; never a general Google key; stated on the security page. ADC is stronger and unverified on a runner.
- [`agy` has no turn or cost limit and its exit code hides refusals] → the guard, the job timeout and the project quota; the pages say what is not enforced.
- [Agent tool names and permission syntax can change between `agy` versions] → the table is compared with the installed tool in a test, the version of `agy` is pinned on the runner, and a mismatch stops the render.
- [A rendered plugin in the repository can be edited by the agent] → protected paths, the hash file, a doctor check; on the runner the plugin is rendered from the pinned package and installed for the machine, so the checked-in copy is not what the run reads.
- [Subagent calls do not block] → the text and the guard, verified in task 1.3 on a real run.
- [Quality of adversarial QA with a Gemini model is unknown] → not claimed; recorded in `docs/pilot-findings.md` after a trial.
- [If the `agy` run on a runner fails task 1.5] → the local adapter ships on its own (groups 2 to 4 and 6 do not depend on group 5) and the cloud step falls back to Gemini CLI's action in a later change.

## Migration Plan

Nothing changes for existing installations (the one edit to a Claude skill is a question in `init`, asked only when the person says they use Antigravity): `agent.build` defaults to `claude`, `relevo init` is additive and the Claude plugin is untouched. The changelog gets an Unreleased entry; the version is raised only when the maintainer prepares a release.
