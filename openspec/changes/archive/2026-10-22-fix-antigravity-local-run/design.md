# Design

## Context

See proposal.md for the problem. `agent-guard.mjs run` reads `--prompt`, `--summary`, `--timeout-minutes`, `--config` and optional lower `--max-turns` / `--max-tokens`, and spawns `agy` itself; the cloud step (`templates/agents/antigravity-step.yml`) already calls it that way with `--timeout-minutes 50`. `planLocalRun` is pure and returns the command that `runLocal` streams in the worktree. `skills/review/SKILL.md` is the single source for Claude Code and for the Antigravity render.

## Goals / Non-Goals

**Goals:**
- The local Antigravity run starts exactly as the cloud one does, minus `--decision` and `--github-output`.
- A test that fails if `go-local` and `agent-guard` disagree on arguments.
- `review` never fails after the pull request exists because of the final branch switch.

**Non-Goals:**
- Changing how the guard counts turns or tokens.
- Writing the `agy` user settings (denied web, allowed commands) for local runs. The cloud step does it; a local run uses the person's own settings. Noted as a known limit, not solved here.
- Changing the interactive Antigravity builder flow (`self` subagent, watchdog, kill).

## Decisions

- **Fix the caller, not the guard.** `planLocalRun` passes `run --prompt "/relevo:go <n>" --config <worktree>/relevo.yml --timeout-minutes <n> --summary <file>`. Alternative: teach the guard a `-- agy -p ...` form; rejected because it would add a second way to call it and the cloud step would not use it.
- **Time limit and summary path.** The time limit is the cloud value (50 minutes) as a constant shared with nothing else for now; the summary goes to the OS temp folder, never into the worktree, so a clean end can remove the worktree and the agent finds it clean. Alternative: a new `relevo.yml` key for the time limit; rejected as scope growth for a value the cloud hardcodes.
- **Test against the real parser.** The new test spawns `node scripts/agent-guard.mjs run ...` built from `planLocalRun`, with `--agy` pointing at a stub script that prints a minimal final event and exits 0 (the guard accepts `--agy <path>`), and asserts exit 0. This runs the real argument parsing without `agy`. The planned command gains no `--agy`; the test adds it.
- **Review step is conditional in the shared skill.** Text: switch back only if `git rev-parse --git-common-dir` equals `git rev-parse --git-dir` (main checkout) and `git worktree list` shows no other worktree on the base branch; otherwise print where it stays. One wording for both agents, so no renderer change. Alternative: put it only in the Antigravity render; rejected because the same failure exists for Claude Code (`go-local` worktrees are detached).
- Of `.agents/`, **only the OpenSpec files are ignored** (`.agents/skills/openspec-*`, `.agents/skills/.openspec-target`, `.agents/workflows/`); `.agents/skills/` also holds skills installed with `npx skills` that `skills-lock.json` tracks, and those stay versioned. They are generated by `openspec init` (about 2,800 lines of text that change with every OpenSpec version) and `.agents/` is a protected path for runs. `.agents/plugins/` is not ignored: `relevo init` installs the Relevo plugin there for the project scope, and a team may want to commit it. Alternative: ignore all of `.agents/`; rejected because it would silently hide that plugin. Teammates on Antigravity regenerate the OpenSpec commands with `openspec init`.

## Risks / Trade-offs

- [The stub event format drifts from what the guard reads] -> the stub is built from the same fixture the guard's own tests use.
- [`.agents/` decision touches the protected-paths rule] -> if it is ignored, the repository's own OpenSpec skills for Antigravity are regenerated with `openspec init`, not shared through git; stated in the changelog.
