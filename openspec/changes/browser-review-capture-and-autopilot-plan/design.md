# Design

## Context

- `scripts/web-review.mjs` runs the agent's review script in a clean Chromium with an origin guard, writes `<out>/web-log.txt` and `<out>/web-result.json` and prints one line per checked line. It never reads `evidence/review-state.json`: the autopilot mode and the person's confirmation of the data are checked only later, by `review-state.mjs precheck|auto`, through the private `driving(state)` of `scripts/lib/review-state.mjs`.
- `review-adapter.mjs` says the capture of `vue/web` is done by "the browser runner", which has no way to take one. `capture.mjs` works only through `adb`; its name rule is `safeCaptureName` in `scripts/lib/device.mjs`.
- `scanReviewScript` (`scripts/lib/web-review.mjs`) refuses modules other than assertion and Playwright, `child_process`, `eval`, `Function`, `process.*`, `fetch` and `import.meta`. It lets through every Playwright call that touches the disk (`screenshot({ path })`, `pdf`, `tracing`, `recordVideo`/`recordHar` through `context.browser().newContext`, `saveAs`, `storageState({ path })`, `setInputFiles`, `routeFromHAR`, `addInitScript|addScriptTag|addStyleTag({ path })`).
- The review script runs in the runner's process, so its `console.log` goes to the runner's stdout unredacted, which the agent reads. A screenshot buffer printed as base64 would put an image in the agent's context.
- `review-state.mjs capture` accepts a path at any time, also after `agree`. `syncState` already resets `agreed` and the audit after a fix.
- `skills/review/SKILL.md` steps 2, 3 and 5 only describe `adb`; the browser path lives in Autopilot item 4. Step 9 switches to the base branch in the main checkout without looking at what runs from it.
- A field report from a Vue review (issue #1 of a pilot project, PR #11): screenshots were asked for after the pull request; the agent wrote its own script with `page.screenshot({ path })`, which the scan and QA passed, though QA noted that `[role="alert"]` could not tell two error shots apart; step 9 had switched to `dev`, which broke the person's Vite server running from the working tree (500 on `/src/App.vue` until restarted); the first run failed as a selector timeout while the cause, a 500, was only in the log; three extra servers were started with `env -u`/`env`, `--strictPort`, polled with curl and stopped with `lsof | kill`, relying on there being no `.env`; captures were recorded after `agree`; every file of `evidence/` was offered for attaching though only the PNGs mattered; `relevo.yml` stayed uncommitted across every branch switch.
- Vite loads `.env`, `.env.local`, `.env.<mode>` and `.env.<mode>.local` by itself. Variables already in the process environment win over those files, so setting a variable works, but unsetting one does not when a file defines it.

## Goals / Non-Goals

**Goals:**
- A browser review takes the screenshots of the shot list during the walk, each one proved by an assertion, without the agent ever seeing them.
- The gates (autopilot, confirmation of the data, agreement, QA of the exact script) hold even if the agent skips a step of the skill.
- Nothing the review script does reaches the disk or the agent's output except through the runner.
- A failing page is reported as a failing page.
- Runs against servers with another configuration are a supported part of the review: started, awaited and stopped by a script that cannot touch the person's server.
- The review never breaks the person's dev server by switching branches under it.
- The person sees the plan of the automatic walk before testing, and the stop message for `autopilot: off` says what to set.

**Non-Goals:**
- The runner does not mark lines; the agent keeps `precheck` and `auto`.
- No change to the device path, to Flutter on the web, to the audit rules or to the origin guard.
- No multi-target call (`--url a,b`); one run per server.
- No temporary worktree for extra servers (see decision 13).

## Decisions

1. **The runner enforces the gates.** `web-review.mjs --state <file>` (default `evidence/review-state.json`). Before `scanReviewScript` and before Playwright is loaded, it reads the state: a missing file, `autopilot: off`, `envConfirmed: false` or `agreed: true` exit 1 with the reason. `driving` is exported from `scripts/lib/review-state.mjs` as `assertDriving` and used by the runner, `precheck` and `auto`, so the messages cannot drift. The state path does not depend on `--out`.
2. **QA is bound to the script's content.** New `review-state.mjs qa-pass <script>` stores `{ path, sha256 }` as `state.qaScript`. The skill runs it only after `relevo:qa` answers `QA PASSED` on that script. The runner computes the hash of `--script` and refuses when it differs or there is none, naming `qa-pass`. Any edit, even one port, needs a new QA pass. `sync` clears `qaScript`.
3. **`capture(name, check, options)`.** `makeCapture({ page, out, captures })` in `scripts/lib/web-review.mjs`: validates the name with `safeCaptureName` (from `scripts/lib/device.mjs`); requires `check` to be a function; accepts only `{ fullPage: boolean }` as options; runs `await check()` first, and on a failure records `{ name, ok: false, error }` and takes no screenshot; otherwise calls `page.screenshot({ path: join(out, '<name>.png'), fullPage })` and records `{ name, ok: true, path }` with the path relative to the working directory. It returns `undefined`, and a failed check does not throw into the script, so the remaining shots still run. Testable with a fake page, without a browser. After the run the runner prints `captured <path>` or `capture <name>: failed (<message>)`, lists all of them as `captures` in `web-result.json`, re-reads the state from disk and appends the saved paths to `state.captures` (re-reading avoids overwriting a `set` made during the run). A repeated name overwrites the file and is recorded once.
4. **Captures belong to the open review.** `review-state.mjs capture` refuses when `state.agreed` is true; the runner already refuses to start then (decision 1). The skill takes the shot list during the walk of step 4. When the person asks for screenshots after the agreement, the agent points to the files already in `evidence/`.
5. **What QA checks in the script.** The instruction of the skill to `relevo:qa` says: every `capture` name is on the shot list; each `check` asserts something that holds only in that shot's state (the text of the alert, the URL, a heading), not a selector shared by two shots; every `THEN` covered by `line` has an assertion that would fail if the feature did not exist.
6. **The scan refuses every direct disk access.** New `FORBIDDEN` rules: `.screenshot(` in any form (the message names `capture(name, check)`), `.pdf(`, `tracing`, `recordVideo`, `recordHar`, `routeFromHAR`, `.saveAs(`, `.storageState(`, `.setInputFiles(`, and any `path:` option key, which also covers `addInitScript`, `addScriptTag` and `addStyleTag`. `capture(` matches none of them.
7. **The script's console goes to a file.** Before it imports the script, the runner replaces `console.log|info|warn|error|debug|trace|dir|table` with a collector and keeps it until the process ends, so a script still running after a timeout cannot print either. The collected lines are redacted and written to `<out>/script-console.txt`. The runner's own lines are printed with the originals, saved at start.
8. **The page's failure comes first.** When `scriptError` is set, the runner looks for the first `pageerror` event or `response` event whose URL has the origin of `--url`, and prints `the page itself failed: <event>` before `the script failed outside a line: <error>`. Both go to stderr; the exit code is unchanged.
9. **One `--out` per run.** The normal run uses `--out evidence`; each run against another server uses `--out evidence/run-<port>`. All share `--state`. When `--out` is not given and `evidence/web-log.txt` already exists, the runner warns on stderr that it is replaced. Step 5 audits only `evidence/web-log.txt`.
10. **A preflight and readiness probe.** `scripts/web-preflight.mjs --url <url> [--timeout 5000] [--wait <ms>]`, logic in `scripts/lib/web-preflight.mjs` with injected file system, resolver and fetch. It checks in order and stops at the first failure, printing JSON `{ ok, check, detail, start, env }`:
    - `node_modules` missing: exit 3;
    - Playwright does not resolve from the project (the resolution of `web-review.mjs`): exit 4;
    - `chromium.executablePath()` does not exist: exit 5;
    - the URL, or a same-origin `<script type="module" src>` of its HTML, does not answer or answers 400 or more after redirects: exit 6, with `detail` (the address and status), `start` (`npm run dev`, else `serve`, else `start`, from `package.json`) and `env` (the variable names of `.env.example`; `.env` and its variants are never read).
    With `--wait`, the URL check is retried every 500 ms until it passes or the time is over; the other checks run once. The skill turns the codes into messages in the person's language. On 4 or 5 it asks permission, runs `npm install --no-save playwright` and `npx playwright install chromium`, then `git diff --quiet -- package-lock.json || git restore -- package-lock.json`, and runs the preflight again. The hint of `web-review.mjs` changes to those commands.
11. **Extra servers belong to a script.** `scripts/extra-server.mjs`, logic in `scripts/lib/extra-server.mjs` with an injected spawner and port probe:
    - `start --port <p> [--set NAME=value ...] [--unset NAME ...] -- <command ...>`: refuses a busy port (exit 3); refuses `--unset` when any file matching `.env` or `.env.*` other than `.env.example` exists in the project folder, checking existence only (exit 4, naming the files); spawns the command detached in its own process group with the environment changed as asked, output to `evidence/servers/<p>.log`; records `{ port, pgid, command }` in `evidence/servers.json`. For Vue the skill passes `npx vite --port <p> --strictPort`.
    - Readiness is `web-preflight.mjs --url http://localhost:<p> --wait 30000`. After it passes, `extra-server.mjs check --port <p>` confirms that the process listening on the port belongs to the recorded group; otherwise the script stops the group and exits 1, so a server that moved to another port is not used.
    - `stop --port <p>` or `stop --all` kills only recorded groups and removes them from the file; a port with no record stops nothing and exits 1.
    The port probe and the listener check use `lsof` on macOS and Linux; where it is missing the script refuses to start (exit 5), and the line stays for the person.
12. **No branch switch under a running server.** `scripts/dev-server-guard.mjs --url <url>`: finds the processes listening on the port of the URL (`lsof -nP -tiTCP:<port> -sTCP:LISTEN`), reads their current folder (`lsof -a -p <pid> -d cwd -Fn`) and compares it, after `realpath`, with the top of the repository. Exit 0: no listener runs from the working tree; exit 1: one does (prints pid and folder); exit 3: it cannot tell (no `lsof`, no permission). Step 9 runs `extra-server.mjs stop --all` first, then switches only on exit 0, and on 1 or 3 stays on the branch and says why (stop the server, then switch).
13. **No temporary worktree.** With captures taken before the agreement (decision 4) and the guard of step 9 (decision 12), nothing after the agreement needs the issue's branch, and the person's server is never switched under. A worktree would only add a folder without `.env` files, at the cost of installing or linking `node_modules`; the rule of decision 11 on `--unset` covers the `.env` case by not running such lines. Left as a possible follow-up.
14. **Uncommitted `relevo.yml`.** Step 0 runs `git status --porcelain -- relevo.yml`; with output, it warns in the person's language that the file has uncommitted changes, that the review uses them, and that they belong on the base branch through their own commit. The review never stages it: the commits of the review go through `commit-change.mjs` with explicit files. The advice of decision 15 says the same.
15. **Advice from the adapter.** `review-adapter.mjs` reads `review.autopilot` and `language` from `relevo.yml` and adds `advice` to its JSON: a fixed text in `en` or `es` when `needs_autopilot` is true and the mode is `off`, else `null`. It recommends `verify`, names `precheck` as the cautious option, says the person confirms every line and appearance is never automatic, and that the setting is committed to the base branch. The texts live in `scripts/lib/review-adapters.mjs`.
16. **The brief note is computed, the plan is the agent's.** `review-brief.mjs --autopilot <mode>` appends one fixed line in the brief's language when the mode is `precheck` or `verify`. The plan of the walk is written by the agent in a fixed format: one line per checklist line, `<n>. <method>: <how>`, method `browser`, `command`, `read` or `server <port>`, then the lines left to the person, then the shot list with the assertion of each shot.
17. **Commands are rules of the skill.** Running `npm run <script>` for a line, `git status --porcelain` before and after, restoring changed tracked files and reporting them, and never running fix or format scripts are written in the Autopilot section and pinned by `tests/skill-review.test.mjs`.
18. **The browser branch of the skill.** Step 0 shows the adapter's `advice` and the `relevo.yml` warning. Step 2 skips `adb`, records `confirm-env`, runs `web-preflight.mjs`. Step 3 tells the person to start the app (the `start` of the preflight) and shows the brief with the plan. Step 4 writes the script, gets `QA PASSED`, runs `qa-pass`, starts extra servers, runs the normal and extra runs, stops the servers. Step 5 audits `evidence/web-log.txt` with `--package web`. Step 8 lists `evidence/**/*.png` only, and deletes the folder without asking when there is none. Step 9 uses the guard.

## Risks / Trade-offs

- The `path:` rule may refuse a harmless script. Mitigation: the message says why; QA sees it before the run.
- `qa-pass` is run by the agent, so it guards against running an edited script by mistake, not against an agent that skips QA on purpose. Accepted: the scan stays a tripwire and QA reads every script.
- A `check` can still be too weak. Mitigation: QA rejects assertions that hold for two shots; the person still looks at the images before attaching them.
- Replacing `console` covers the console only; an error message of the script can hold data, which the runner already prints as one redacted line. Accepted.
- Runs now need a state and a QA hash, so a manual run outside a review is refused. Accepted: the runner exists for the review.
- `lsof` is missing on Windows and may lack permission elsewhere. Mitigation: both scripts fail safe (no extra server, no branch switch) and say why.
- An extra server may keep running if the agent is stopped midway. Mitigation: it is recorded in `evidence/servers.json`; step 9 and a resumed review run `stop --all`.
- `npm install --no-save` can still rewrite `package-lock.json`. Mitigation: the restore step; the person's permission comes first.
- `tests/web-review-run.test.mjs` needs a state fixture with a QA hash in every test. Accepted: it also proves the gates.
